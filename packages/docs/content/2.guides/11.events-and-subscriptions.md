## Event System

The engine emits typed events for every state change. Register listeners with `on()`, one-shot listeners with `once()`, and remove them with `off()`:

```ts
// Subscribe
const unsub = engine.on('node:created', (node) => {
  console.log('Created:', node.id, node.type)
})

// One-time listener
engine.once('ready', () => {
  console.log('Engine is ready')
})

// Unsubscribe (using the returned function)
unsub()
```

## Event Catalog

### Lifecycle

| Event | Handler | When |
| --- | --- | --- |
| `ready` | `() => void` | Engine initialization complete. |
| `destroy` | `() => void` | Engine is being torn down. |

### Node events

| Event | Handler | When |
| --- | --- | --- |
| `node:created` | `(node) => void` | A node was added. |
| `node:updated` | `(node, prev) => void` | A node's properties changed. |
| `node:deleted` | `(id, prev) => void` | A node was removed. |
| `node:moved` | `(node, delta) => void` | A node changed position. |
| `node:resized` | `(node, prev) => void` | A node changed dimensions. |

### Selection and interaction

| Event | Handler | When |
| --- | --- | --- |
| `selection:change` | `(selected, prev) => void` | Selection changed. |
| `interaction:start` | `(state) => void` | An interaction began (drag, resize, pan, etc.). |
| `interaction:update` | `(state) => void` | An active interaction updated (pointer moved). |
| `interaction:end` | `(state) => void` | An interaction ended. |

### Command pipeline

| Event | Handler | When |
| --- | --- | --- |
| `command:before` | `(name, args) => void` | A command is about to execute. |
| `command:after` | `(name, args, duration) => void` | A command completed. |
| `command:blocked` | `(name, args) => void` | A command was blocked by middleware. |

### Diagnostics

| Event | Handler | When |
| --- | --- | --- |
| `invariant:failed` | `(failure) => void` | A state invariant was violated. |

### Plugin events

Plugins add their own events. With the connections plugin:

| Event | Handler |
| --- | --- |
| `edge:created` | `(edge) => void` |
| `edge:deleted` | `(edgeId) => void` |

With the history plugin:

| Event | Handler |
| --- | --- |
| `history:push` | `(entry) => void` |
| `history:undo` | `(entry) => void` |
| `history:redo` | `(entry) => void` |
| `history:clear` | `() => void` |

## Subscribables

For fine-grained reactivity, the engine exposes five subscribables that notify only when their specific slice of state changes:

```ts
engine.$camera.subscribe((current, prev) => {
  // Only fires when the camera changes
})

engine.$nodes.subscribe((nodes, prev) => {
  // Only fires when any node changes
})

engine.$selection.subscribe((selected, prev) => {
  // Only fires when the selection changes
})
```

### Subscribable vs. events

- **Events** are specific actions: `node:created` fires once per node creation.
- **Subscribables** are state snapshots: `$nodes` fires whenever the node map changes, regardless of which command caused it.

In Vue, composables like `useCamera()` and `useNodes()` wrap subscribables into reactive `ComputedRef` values.

## Batching

`engine.batch()` groups operations so subscribable notifications fire once at the end:

```ts
engine.batch(() => {
  engine.createNode({ type: 'text', x: 0, y: 0, data: { content: 'A' } })
  engine.createNode({ type: 'text', x: 200, y: 0, data: { content: 'B' } })
  // $nodes.subscribe fires once, after both nodes exist
})
```

Note: individual events (`node:created`) still fire for each operation inside the batch — only subscribable notifications are deferred.

## Diagnostics Trace

With diagnostics enabled (default), every event is recorded in a trace buffer:

```ts
const trace = engine.exportTrace()
const last = trace[trace.length - 1]
console.log(last.event, last.timestamp, last.args)
```

The trace buffer is capped at `traceLimit` (default 500 entries).
