Events tell you what happened. Subscriptions tell you what state looks like now.

::event-logger
::

::tip
This is the main distinction: events are action-shaped, subscribables are state-shaped.
::

## Quick example

```ts
const unsub = engine.on('node:created', (node) => {
  console.log('Created', node.id)
})

engine.$nodes.subscribe((nodes) => {
  console.log('Node count', nodes.size)
})
```

## Event catalog

::accordion
::accordion-item{label="Lifecycle" icon="i-lucide-circle-help"}
`ready`, `destroy`
::

::accordion-item{label="Node events" icon="i-lucide-circle-help"}
`node:created`, `node:updated`, `node:deleted`, `node:moved`, `node:resized`
::

::accordion-item{label="Selection and interaction" icon="i-lucide-circle-help"}
`selection:change`, `interaction:start`, `interaction:update`, `interaction:end`
::

::accordion-item{label="Command pipeline" icon="i-lucide-circle-help"}
`command:before`, `command:after`, `command:blocked`
::

::accordion-item{label="Plugin events" icon="i-lucide-circle-help"}
Plugins add their own namespaced events like `edge:created`, `edge:deleted`, and history-specific state changes.
::

::

::collapsible
### When should I use which?

Use events when you want to react to a discrete action like “a node was created” or “a command was blocked.” Use subscriptions when you want to keep UI in sync with the latest state snapshot.
::
