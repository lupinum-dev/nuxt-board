## The Engine

Every board starts with a `BoardEngine`. The engine is the single source of truth — it owns all state (camera, nodes, selection, interaction), processes all mutations through commands, and emits events. It has zero DOM or framework dependencies.

```ts
import { createBoardEngine } from '@lupinum/board-core'

const engine = createBoardEngine({
  grid: { size: 20, snap: true, pattern: 'line' },
  zoom: { min: 0.1, max: 8 },
})
```

The engine is headless. Vue rendering, DOM events, and keyboard shortcuts are handled by `@lupinum/vue-board` components that subscribe to the engine's reactive state.

### Type-safe node data

The engine accepts a generic type parameter `R` that maps node type strings to their data shape:

```ts
type MyRegistry = {
  text: { content: string }
  image: { src: string; alt: string }
  group: { title: string; accent: string }
}

const engine = createBoardEngine<MyRegistry>()

// TypeScript knows data must be { content: string }
engine.createNode({ type: 'text', x: 0, y: 0, data: { content: 'Hello' } })
```

## Board State

The engine maintains six pieces of state, all accessible via reactive subscribables:

| State | Subscribable | Type | Description |
| --- | --- | --- | --- |
| Camera | `$camera` | `Camera` | Position `{ x, y }` and zoom `z`. |
| Nodes | `$nodes` | `Map<NodeId, BoardNode>` | All nodes keyed by ID. |
| Selection | `$selection` | `Set<NodeId>` | Currently selected node IDs. |
| Interaction | `$interaction` | `InteractionState` | Active interaction mode (idle, panning, dragging, etc.). |
| Snap guides | `$snapGuides` | `SnapGuide[]` | Alignment guides shown during drag/resize. |
| Next z-index | *(internal)* | `number` | Auto-incrementing z-order counter. |

Each subscribable exposes `get()` for synchronous reads and `subscribe()` for reactive updates:

```ts
// Synchronous read
const zoom = engine.$camera.get().z

// Reactive subscription
engine.$camera.subscribe((camera, prev) => {
  console.log(`Zoom changed: ${prev.z} → ${camera.z}`)
})
```

In Vue, the `@lupinum/vue-board` composables wrap these into `ComputedRef` values automatically — you rarely need to call `subscribe()` directly.

## Nodes

Nodes are immutable records with geometry, type, data, and optional hierarchy:

```ts
interface BoardNode {
  id: NodeId           // branded string
  type: string         // 'text', 'image', 'group', etc.
  x: number            // world-space position
  y: number
  width: number        // dimensions
  height: number
  data: Record<string, unknown>  // type-specific payload
  zIndex: number       // rendering order
  locked: boolean      // prevents move/resize
  visible: boolean     // hidden from queries and rendering
  parentId?: NodeId    // parent group (hierarchy)
}
```

Nodes are never mutated directly. All changes go through engine commands:

```ts
// Create
const node = engine.createNode({ type: 'text', x: 100, y: 200, data: { content: 'Card' } })

// Update
engine.updateNode(node.id, { data: { content: 'Updated' } })

// Move
engine.moveNode(node.id, 50, 0)  // move right 50px

// Delete
engine.deleteNode(node.id)
```

## Commands

Every mutation flows through the engine's command pipeline:

```
Middleware chain → command:before event → mutation → invariant validation → command:after event
```

This architecture gives you:

- **Middleware interception** — block or modify commands before they execute
- **Event hooks** — react to any change (node created, selection changed, etc.)
- **Invariant validation** — catch invalid state immediately
- **Plugin integration** — plugins hook into commands, not raw state
- **Diagnostics** — every command is traced with timing

Commands include: `createNode`, `updateNode`, `deleteNode`, `moveNode`, `resizeNode`, `select`, `panBy`, `zoomToFit`, and many more. See the [engine API reference](/api/board-core) for the full list.

### Batching

When you need multiple operations to be treated as a single update:

```ts
engine.batch(() => {
  engine.createNode({ type: 'text', x: 0, y: 0, data: { content: 'A' } })
  engine.createNode({ type: 'text', x: 300, y: 0, data: { content: 'B' } })
  // Subscribers are notified once, after both nodes exist
})
```

## Interaction State Machine

The engine models pointer interactions as a discriminated union with six modes:

| Mode | When | What happens |
| --- | --- | --- |
| `idle` | No interaction | Default state. |
| `panning` | Space+drag or middle mouse | Camera moves. |
| `dragging-nodes` | Drag a node | Selected nodes move (with snap guides). |
| `resizing-node` | Drag a resize handle | Node dimensions change (with constraints). |
| `box-select` | Drag on empty canvas | Nodes inside the box are selected. |
| `editing-text` | Double-click a node | A text editor appears. |

You drive the state machine by calling `begin*()` and `endInteraction()`:

```ts
engine.beginNodeDrag(nodeId, pointerId, screenPoint)
engine.updatePointer(pointerId, newScreenPoint)  // called on every pointer move
engine.endInteraction(pointerId)                  // finalizes the drag
```

`BoardRoot` handles this automatically for pointer and keyboard events — you only need these methods for programmatic interactions.

## Rendering

`BoardRoot` is the Vue component that renders the board. It subscribes to the engine and handles:

- Viewport transform (scale + translate from camera)
- Node rendering with viewport culling (only visible nodes are mounted)
- Level-of-detail (LOD) — nodes shrink to placeholders when zoomed out
- Pointer events (drag, resize, pan, box select, double-click)
- Keyboard shortcuts
- Grid rendering

```vue
<script setup lang="ts">
import { createBoardEngine } from '@lupinum/board-core'
import { BoardRoot } from '@lupinum/vue-board'

const engine = createBoardEngine()
</script>

<template>
  <BoardRoot :engine="engine" class="h-screen" />
</template>
```

Custom renderers replace only the node content — selection, dragging, resizing, and z-ordering stay with the board shell. See the [renderers guide](/guides/renderers-and-layout).

## Plugins

Plugins extend the engine with new capabilities. They receive a `BoardPluginContext` that adds `emit()`, `extend()`, and `runCommand()` to the engine interface.

```ts
import { historyPlugin } from '@lupinum/board-history'
import { connectionPlugin } from '@lupinum/board-connections'

const engine = createBoardEngine({
  plugins: [
    historyPlugin({ maxSteps: 100 }),
    connectionPlugin({ routing: 'bezier' }),
  ],
})

// Plugins register their API on engine.ext
engine.ext.history.undo()
engine.ext.connections.createEdge({ from: nodeA, to: nodeB, data: {} })
```

Official plugins:

| Package | What it adds |
| --- | --- |
| `@lupinum/board-history` | Undo/redo with debouncing. |
| `@lupinum/board-connections` | Edges between nodes with routing. |
| `@lupinum/board-minimap` | Minimap composable and component. |
| `@lupinum/board-selection` | Selection utility functions. |
| `@lupinum/board-serializer` | JSON Canvas import/export. |

See the [plugins guide](/guides/plugins) for building your own.

## Events

The engine emits typed events for every state change:

```ts
engine.on('node:created', (node) => {
  console.log('New node:', node.id)
})

engine.on('selection:change', (selected, prev) => {
  console.log(`${selected.length} nodes selected`)
})

engine.on('command:after', (name, args, duration) => {
  console.log(`${name} took ${duration.toFixed(1)}ms`)
})
```

Events cover node lifecycle, camera changes, selection, interaction, commands, and plugin-specific events. See the [events guide](/guides/events-and-subscriptions) for the full catalog.
