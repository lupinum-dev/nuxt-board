## Viewport Culling

`BoardRoot` only renders nodes within the viewport plus a configurable margin. Nodes outside this area are completely unmounted from the DOM:

```vue
<BoardRoot :engine="engine" :cull-margin="200" />
```

The default margin is 200 world units. Increase it if you see nodes popping in during fast panning; decrease it for better performance with many nodes.

---

## Level of Detail (LOD)

Nodes are rendered at three detail levels based on their screen-space size:

| LOD | Condition | What renders |
| --- | --- | --- |
| `full` | Selected, or screen size >= 120px | Full custom renderer, handles, text. |
| `simple` | Screen size 8–120px | Lightweight placeholder with stripe pattern. |
| `hidden` | Screen size < 8px | Not rendered at all. |

Selected nodes always render at `full` detail. This means zooming out on a large board only renders simplified boxes — dramatically reducing DOM complexity.

---

## v-memo Optimization

`BoardRoot` uses Vue's `v-memo` to skip re-rendering nodes when their relevant props haven't changed. A node only re-renders when its position, size, z-index, LOD, selection, or editing state changes.

---

## RAF Throttling

Pointer move events are throttled to one `engine.updatePointer()` call per animation frame via `requestAnimationFrame`. This prevents overwhelming the engine during fast drags.

---

## Batching

Use `engine.batch()` when creating many nodes at once to reduce notification overhead:

```ts
engine.batch(() => {
  for (let i = 0; i < 100; i++) {
    engine.createNode({
      type: 'text',
      x: i * 260,
      y: 0,
      data: { content: `Node ${i}` },
    })
  }
  // One notification instead of 100
})
```

---

## Subscribable Granularity

The five subscribables (`$camera`, `$nodes`, `$selection`, `$interaction`, `$snapGuides`) fire independently. A camera change does not trigger a `$nodes` notification. This prevents cascading re-renders in Vue's reactivity system.

---

## Best Practices

- **Don't wrap the engine in `ref()` or `reactive()`** — the engine manages its own reactivity through subscribables. Use `shallowRef` if you need to store it.
- **Prefer composables** — `useCamera()`, `useNodes()`, etc. already provide granular reactivity.
- **Keep node data immutable** — create new objects for updates instead of mutating `data` in place.
- **Use `cullMargin`** — tune it for your use case. Lower values = fewer rendered nodes = better performance.
- **Batch bulk operations** — wrap multi-node operations in `engine.batch()`.
