## How Rendering Works

`BoardRoot` renders nodes in a layered pipeline:

1. **Viewport culling** — only nodes within the viewport (+ margin) are considered
2. **Level of detail** — nodes too small on screen render as simplified placeholders
3. **Renderer resolution** — for each visible node, the board resolves which content to show

The board shell handles positioning, selection outlines, resize handles, and z-ordering. Your custom renderer only needs to display the node's content.

---

## The Renderer Registry

Map node type strings to Vue components via the `renderers` prop on `BoardRoot`:

```vue
<script setup lang="ts">
import { createBoardEngine } from '@lupinum/board-core'
import { BoardRoot, type BoardRendererRegistry } from '@lupinum/vue-board'
import MyImageNode from './MyImageNode.vue'
import MyGroupNode from './MyGroupNode.vue'

const engine = createBoardEngine()

const renderers: BoardRendererRegistry = {
  image: MyImageNode,
  group: MyGroupNode,
}
</script>

<template>
  <BoardRoot :engine="engine" :renderers="renderers" class="h-screen" />
</template>
```

Nodes with types not in the registry use the built-in text renderer (or the `fallbackRenderer` if set).

## Writing a Custom Renderer

A renderer is a standard Vue component that receives props from the board:

```vue
<!-- MyImageNode.vue -->
<script setup lang="ts">
import type { BoardNode } from '@lupinum/board-core'

const props = defineProps<{
  node: BoardNode
  selected: boolean
  editing: boolean
  beginEdit: () => void
  commitText: (text: string) => void
}>()
</script>

<template>
  <div class="image-node">
    <img
      v-if="node.data.src"
      :src="node.data.src"
      :alt="node.data.alt"
      class="w-full h-full object-cover"
    />
    <div v-else class="placeholder">
      No image
    </div>
  </div>
</template>
```

### Props your renderer receives

| Prop | Type | Description |
| --- | --- | --- |
| `node` | `BoardNode` | The node data (position, size, data, etc.). |
| `selected` | `boolean` | Whether the node is currently selected. |
| `editing` | `boolean` | Whether the node is in text editing mode. |
| `beginEdit` | `() => void` | Start text editing (call to enter editing mode). |
| `commitText` | `(text: string) => void` | Commit text and end editing. |

Your renderer fills the node's bounding box. The board sets `width` and `height` on the node's container — your component should use `width: 100%` and `height: 100%`.

## Accessing the Engine from Renderers

Use `useBoardEngine()` inside your renderer to access the engine and call commands:

```vue
<script setup lang="ts">
import type { BoardNode } from '@lupinum/board-core'
import { useBoardEngine } from '@lupinum/vue-board'

const props = defineProps<{ node: BoardNode; selected: boolean; editing: boolean }>()
const { engine } = useBoardEngine()

function updateTitle(newTitle: string) {
  engine.updateNode(props.node.id, {
    data: { ...props.node.data, title: newTitle },
  })
}
</script>
```

## Slot-Based Rendering

Instead of (or in addition to) the renderer registry, you can use named slots on `BoardRoot`:

### Type-specific slot

```vue
<BoardRoot :engine="engine">
  <template #node:image="{ node, selected }">
    <img :src="node.data.src" class="w-full h-full object-cover" />
  </template>
</BoardRoot>
```

### Fallback slot

```vue
<BoardRoot :engine="engine">
  <template #node="{ node }">
    <div class="generic-node">{{ node.type }}: {{ node.data }}</div>
  </template>
</BoardRoot>
```

### Resolution order

1. `#node:{type}` named slot (highest priority)
2. `#node` fallback slot
3. `renderers[type]` from the renderer registry
4. `fallbackRenderer` prop
5. Built-in text renderer (lowest priority)

## Handling Edit Mode

If your node type supports inline editing, use the `editing` prop and `beginEdit`/`commitText`:

```vue
<script setup lang="ts">
import { ref, watch } from 'vue'

const props = defineProps<{
  node: BoardNode
  selected: boolean
  editing: boolean
  beginEdit: () => void
  commitText: (text: string) => void
}>()

const draft = ref(props.node.data.title)

watch(() => props.editing, (isEditing) => {
  if (!isEditing) {
    draft.value = props.node.data.title
  }
})

function save() {
  props.commitText(draft.value)
}
</script>

<template>
  <div @dblclick="beginEdit">
    <textarea
      v-if="editing"
      v-model="draft"
      data-editor="true"
      @blur="save"
      @keydown.enter.meta.prevent="save"
      @keydown.esc.prevent="commitText(node.data.title)"
    />
    <span v-else>{{ node.data.title }}</span>
  </div>
</template>
```

Mark the editable element with `data-editor="true"` so `BoardRoot` knows to let keyboard events pass through instead of triggering shortcuts.

## Custom Resize Handles

Override the resize handle appearance with the `handle` slot:

```vue
<BoardRoot :engine="engine">
  <template #handle="{ handle }">
    <div
      class="my-custom-handle"
      :data-resize="handle"
    />
  </template>
</BoardRoot>
```

The `data-resize` attribute is required — `BoardRoot` uses it to identify which handle was clicked.

## Level of Detail (LOD)

`BoardRoot` automatically assigns one of three LOD levels to each node based on its screen-space size:

| LOD | Condition | What renders |
| --- | --- | --- |
| `full` | Selected, or >= 120px on screen | Your custom renderer (or built-in). |
| `simple` | 8–120px on screen | A minimal placeholder with stripe pattern. |
| `hidden` | < 8px on screen | Nothing (unmounted from DOM). |

Selected nodes always render at `full` LOD regardless of size.
