## The Camera Model

The camera is defined by three values:

```ts
interface Camera {
  x: number  // horizontal offset in world units
  y: number  // vertical offset in world units
  z: number  // zoom level (1 = 100%)
}
```

`z = 1` means no zoom. Values less than 1 zoom out (show more), values greater than 1 zoom in (show less). The default zoom range is `0.1` to `8`.

```ts
const engine = createBoardEngine({
  camera: { x: 0, y: 0, z: 1 },    // starting position
  zoom: { min: 0.1, max: 8 },       // allowed zoom range
})
```

## Panning

### panBy

Pans the camera by a world-space delta. Positive `dx` moves the camera right (content moves left):

```ts
engine.panBy(100, 0)   // pan right 100
engine.panBy(0, -50)   // pan up 50
```

### panTo

Pans the camera to center on a world-space point. Optionally animates the transition:

```ts
// Instant
await engine.panTo({ x: 500, y: 300 })

// Animated (smooth transition)
await engine.panTo({ x: 500, y: 300 }, true)
```

## Zooming

### zoomAt

Zooms relative to a screen-space point. The point stays fixed on screen (zoom follows the cursor). Positive `delta` zooms out, negative zooms in:

```ts
engine.zoomAt({ x: 640, y: 360 }, -50)  // zoom in at center
engine.zoomAt({ x: 640, y: 360 }, 50)   // zoom out at center
```

### zoomTo

Sets the zoom level directly:

```ts
await engine.zoomTo(2, true)    // zoom to 200%, animated
await engine.zoomTo(0.5, true)  // zoom to 50%, animated
await engine.zoomTo(1)          // zoom to 100%, instant
```

### zoomToFit

Adjusts the camera so all nodes fit in the viewport with optional padding:

```ts
await engine.zoomToFit(40, true)  // fit all nodes with 40px padding, animated
```

### zoomToNodes

Same as `zoomToFit`, but for a specific set of nodes:

```ts
await engine.zoomToNodes([nodeA, nodeB], 40, true)
```

## Coordinate Conversion

The engine provides methods to convert between screen-space (pixel coordinates relative to the board element) and world-space (the infinite canvas):

```ts
// Screen → World: useful for hit testing pointer events
const worldPos = engine.screenToWorld({ x: event.clientX, y: event.clientY })

// World → Screen: useful for overlays and tooltips
const screenPos = engine.worldToScreen({ x: node.x, y: node.y })
```

### Visible bounds

Get the world-space area currently visible in the viewport:

```ts
const bounds = engine.getVisibleBounds(viewportWidth, viewportHeight)
// { minX, minY, maxX, maxY }
```

Or reactively in Vue:

```vue
<script setup lang="ts">
import { useVisibleBounds, useCamera } from '@lupinum/vue-board'

const bounds = useVisibleBounds()
const camera = useCamera()
</script>
```

## Viewport Size

`BoardRoot` automatically tracks the viewport size via `ResizeObserver` and calls `engine.setViewportSize()`. You can read it with:

```ts
const { x: width, y: height } = engine.getViewportSize()
```

---

## Viewport Culling

`BoardRoot` only renders nodes that are within the viewport plus a margin (`cullMargin`, default 200 world units). This keeps performance stable even with thousands of nodes.

```vue
<BoardRoot :engine="engine" :cull-margin="300" />
```

Nodes outside the margin are completely unmounted from the DOM — they don't consume render time or memory.

---

## Animations

Methods that accept an `animated` parameter (`panTo`, `zoomTo`, `zoomToFit`, `zoomToNodes`) return a `Promise` that resolves when the animation completes. Animations use `requestAnimationFrame` with smooth interpolation via `lerpCamera()`.

Starting a new animated transition cancels any in-progress animation.

---

## Camera Events

```ts
engine.on('camera:change', (camera, prev) => {
  console.log(`Zoom: ${prev.z.toFixed(2)} → ${camera.z.toFixed(2)}`)
})
```

Camera changes from panning and zooming are high-frequency — consider throttling if you're doing expensive work in the handler.
