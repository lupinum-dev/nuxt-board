Plugins add capability. Middleware controls whether commands are allowed to run.

::read-only-toggle-demo
::

## Install a plugin

```ts
import { historyPlugin } from '@lupinum/board-history'
import { connectionPlugin } from '@lupinum/board-connections'

const engine = createBoardEngine({
  plugins: [historyPlugin(), connectionPlugin({ routing: 'step' })],
})
```

::note
Plugins are for new capabilities. Middleware is for policy, auditing, or blocking commands.
::

## Build your first plugin

::steps{level="3"}

### Define the plugin

```ts
import type { BoardPlugin } from '@lupinum/board-core'

const loggerPlugin: BoardPlugin = {
  name: 'logger',
  install(ctx) {
    ctx.on('command:after', (name) => {
      console.log('[board]', name)
    })
  },
}
```

### Install it

```ts
const engine = createBoardEngine({
  plugins: [loggerPlugin],
})
```

### Extend the engine if needed

```ts
ctx.extend('logger', {
  clear() {
    console.clear()
  },
})
```

::

## Middleware

Middleware runs before the command executes. Call `next()` to allow it, or return early to block it.

```ts
engine.addMiddleware((name, _args, next) => {
  if (name === 'deleteSelected') {
    return
  }
  next()
})
```

::warning
If middleware blocks a command, nothing happens unless your app surfaces that outcome. Listen to `command:blocked` if the user needs feedback.
::
