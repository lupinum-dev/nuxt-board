Vue Board stays fast with large boards through three automatic optimizations: viewport culling hides off-screen nodes, LOD simplifies distant ones, and RAF throttling limits pointer updates. Your part is to batch bulk operations and avoid reactive wrappers.

## Viewport culling

`BoardRoot` only renders nodes within the viewport plus a configurable margin. Nodes outside are completely unmounted from the DOM:

```vue
<BoardRoot :engine="engine" :cull-margin="200" />
```

::tip
Increase `cull-margin` if you see nodes popping in during fast panning. Decrease it for better performance with many nodes.
::

## Level of Detail (LOD)

| LOD | Condition | What renders |
| --- | --- | --- |
| `full` | Selected, or >= 120px on screen | Full custom renderer. |
| `simple` | 8–120px | Lightweight placeholder with stripe pattern. |
| `hidden` | < 8px | Nothing (unmounted). |

Selected nodes always render at `full` detail. Zooming out on a large board only renders simplified boxes — dramatically reducing DOM complexity.

## Batching

Use `engine.batch()` when creating many nodes at once:

```ts
engine.batch(() => {
  for (let i = 0; i < 100; i++) {
    engine.createNode({
      type: 'text',
      x: i * 260, y: 0,
      data: { content: `Node ${i}` },
    })
  }
  // One notification instead of 100
})
```

## Best practices

::tip
Don't wrap the engine in `ref()` or `reactive()`. The engine manages its own reactivity through subscribables. Use `shallowRef` if you need to store it.
::

::tip
Prefer composables — `useCamera()`, `useNodes()`, etc. — over subscribing manually. They give granular reactivity without cascading re-renders.
::

::tip
Keep node data immutable. Create new objects for updates instead of mutating `data` in place.
::

::tip
Batch bulk operations. Wrap multi-node creation or updates in `engine.batch()` to reduce notification overhead.
::

::collapsible
### v-memo optimization

`BoardRoot` uses Vue's `v-memo` to skip re-rendering nodes when their relevant props haven't changed. A node only re-renders when its position, size, z-index, LOD, selection, or editing state changes.
::

::collapsible
### RAF throttling

Pointer move events are throttled to one `engine.updatePointer()` call per animation frame via `requestAnimationFrame`. This prevents overwhelming the engine during fast drags.
::

::collapsible
### Subscribable granularity

The five subscribables (`$camera`, `$nodes`, `$selection`, `$interaction`, `$snapGuides`) fire independently. A camera change does not trigger a `$nodes` notification. This prevents cascading re-renders in Vue's reactivity system.
::
