Events tell you what happened. Subscribables tell you what state looks like now. Use events to react to discrete actions, use subscribables to keep your UI in sync.

::event-logger
::

## Events

Register a listener with `engine.on()`. It returns an unsubscribe function:

```ts
const unsub = engine.on('node:created', (node) => {
  console.log('Created', node.id)
})

// Later...
unsub()
```

### Event catalog

::accordion

::accordion-item{label="Lifecycle" icon="i-lucide-power"}
- `ready` — engine initialized
- `destroy` — engine destroyed
::

::accordion-item{label="Node events" icon="i-lucide-square"}
- `node:created(node)` — a node was added
- `node:updated(node, previousNode)` — a node's data or geometry changed
- `node:deleted(nodeId, previousNode)` — a node was removed
- `node:moved(node, delta)` — a node's position changed
- `node:resized(node, previousNode)` — a node's dimensions changed
::

::accordion-item{label="Selection and interaction" icon="i-lucide-mouse-pointer"}
- `selection:change(selectedIds, previousIds)` — selection changed
- `interaction:start(state)` — an interaction began (drag, resize, pan, etc.)
- `interaction:update(state)` — ongoing interaction position updated (high-frequency)
- `interaction:end(state)` — interaction finished
::

::accordion-item{label="Camera" icon="i-lucide-move"}
- `camera:change(camera, previousCamera)` — camera position or zoom changed (high-frequency during pan/zoom)
::

::accordion-item{label="Command pipeline" icon="i-lucide-terminal"}
- `command:before(commandName, args)` — a command is about to execute
- `command:after(commandName, args)` — a command finished executing
- `command:blocked(commandName, args)` — a command was blocked by middleware
::

::accordion-item{label="Plugin events" icon="i-lucide-puzzle"}
Plugins add their own namespaced events:
- **Connections:** `edge:created(edge)`, `edge:updated(edge, prev)`, `edge:deleted(edgeId)`
- **History:** `history:push(entry)`, `history:undo()`, `history:redo()`, `history:clear()`
::

::

## Subscribables

Five subscribables give you reactive access to engine state. Each fires independently — a camera change does not trigger a `$nodes` notification:

::tabs

:::tabs-item{label="$nodes" icon="i-lucide-square"}
```ts
engine.$nodes.subscribe((nodes) => {
  console.log('Node count:', nodes.size)
})
```

Fires when any node is created, updated, moved, resized, or deleted.
:::

:::tabs-item{label="$camera" icon="i-lucide-move"}
```ts
engine.$camera.subscribe((camera) => {
  console.log(`Zoom: ${camera.z.toFixed(2)}`)
})
```

Fires on every pan and zoom change. High-frequency during interaction.
:::

:::tabs-item{label="$selection" icon="i-lucide-check-square"}
```ts
engine.$selection.subscribe((ids) => {
  console.log('Selected:', ids.length)
})
```

Fires when the selection set changes.
:::

:::tabs-item{label="$interaction" icon="i-lucide-hand"}
```ts
engine.$interaction.subscribe((state) => {
  console.log('Mode:', state.mode)
})
```

Fires when the interaction state machine transitions.
:::

:::tabs-item{label="$snapGuides" icon="i-lucide-ruler"}
```ts
engine.$snapGuides.subscribe((guides) => {
  console.log('Active guides:', guides.length)
})
```

Fires when snap alignment guides appear or disappear.
:::

::

::tip
In Vue, prefer the composables (`useCamera()`, `useNodes()`, `useSelection()`) over raw subscribables. They handle reactivity automatically.
::

::note
Inside `engine.batch()`, events fire for each individual command but subscribable notifications are deferred until the batch completes.
::
