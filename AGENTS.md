# Repository instructions

## Purpose

Nuxt Board is a fixed-version package family for node-based editors in Vue and
Nuxt. The headless engine owns board state and commands. Vue and Nuxt adapt the
engine to their frameworks.

Keep one document model, one command engine, and one interaction contract. Do
not add a second state model, renderer protocol, or compatibility path without
an accepted design decision.

## Repository map

- `packages/board-core/` contains the headless model, commands, and types.
- `packages/vue-board/` contains Vue rendering and interaction adapters.
- `packages/board-history/` contains undo and redo behavior.
- `packages/board-connections/` contains edges, routing, and Vue rendering.
- `packages/nuxt-board/` contains the Nuxt module and its fixtures.
- `apps/docs/` contains the public Ginko Docs site.
- `docs/WRITING.md` defines the public writing profile.
- `apps/playground/` contains the development application.
- `scripts/` contains direct package verification operations.
- `ARCHITECTURE.md` records the package and dependency boundaries.
- `MAINTAINING.md` contains the human release and recovery procedure.

## Sources of truth

- The package manifests own package names, versions, exports, and commands.
- `.changeset/config.json` owns the fixed-version package group.
- Changeset files own version intent for unreleased changes.
- `CHANGELOG.md` owns published release history and is generated by Changelogen.
- `pnpm-lock.yaml` owns resolved dependencies.
- `packages/board-core/` owns the board document and command contracts.
- `apps/docs/app/app.config.ts` owns the documentation identity.
- `apps/docs/content/docs/` owns public guidance.

Do not hand-edit generated files under `.nuxt/`, `.output/`, `dist/`, or
`.pack-check/`.

## Commands

Use the Node and pnpm versions declared by the repository.

```bash
pnpm install --frozen-lockfile
pnpm dev:playground
pnpm verify
```

Use these focused commands during development:

- `pnpm format` formats supported files.
- `pnpm lint` checks source and documentation rules.
- `pnpm typecheck` checks the workspace, docs, and Nuxt fixtures.
- `pnpm test:unit` runs the unit and Nuxt module tests.
- `pnpm test:e2e` runs browser interaction and visual tests.
- `pnpm test:docs` checks and builds the documentation site.
- `pnpm pack:check` verifies all five packed packages in clean consumers.
- `pnpm release:verify` runs the final release-candidate gate.

Run the smallest relevant test while you work. Run `pnpm verify` before you
finish. Run `pnpm test:e2e` when interaction or screenshot behavior changes.

## Architecture boundaries

- Framework-neutral behavior stays in `board-core`.
- Vue packages render state and translate DOM input. They do not own domain
  state.
- The Nuxt module registers supported imports and components. It does not own
  board behavior.
- Public snapshots are immutable. Commands own mutations.
- Plugins extend the engine through the existing typed plugin contract.
- The five public packages use one fixed release version.
- Server rendering must not require browser globals.

Keep domain logic out of Vue components, Nuxt hooks, and transport adapters.

## Tests and documentation

Add tests for invariants and failure behavior, not only successful output.
Update public documentation when an API, default, limitation, or package
boundary changes.

Use ASD-STE100-style controlled English for explanatory text. Prefer short
sentences, one instruction per step, and one term for each concept. Do not
rewrite code, API names, quotations, license text, or generated reports to
match this writing profile.

## Publication safety

Agents must not:

- Publish an npm package.
- Approve an npm deployment.
- Move an npm dist-tag.
- Create or push a release tag.
- Change npm trusted-publisher settings.
- Handle, request, or store publication credentials.

Agents can prepare and verify release artifacts. A human maintainer performs
registry approvals and external configuration.

The release workflow runs `pnpm release:version`. Changesets updates package
versions. Changelogen updates `CHANGELOG.md`. Do not use Changelogen to commit,
tag, push, or publish.

## Change policy

Use a short branch name that describes the work, such as
`fix/selection-recovery`. Do not require an agent or tool prefix such as
`codex/`, `claude/`, or `cursor/`.

Prefer deletion and simplification. Do not add generic adapters, wrappers,
configuration, caches, state machines, or compatibility paths for possible
future use.

Create a Changeset for a change to a published package. Keep one concern in
each pull request.
