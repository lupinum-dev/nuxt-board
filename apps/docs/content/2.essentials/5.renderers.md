Custom renderers make nodes look like your product, not the default text box. The board shell still handles positioning, selection, resize handles, and z-ordering — your renderer only draws content.

::renderer-board-demo
::

## The renderer registry

Map node `type` strings to Vue components via the `renderers` prop:

```vue
<script setup lang="ts">
import { createBoardEngine } from '@lupinum/board-core'
import type { BoardRendererRegistry } from '@lupinum/vue-board'
import MyImageNode from './MyImageNode.vue'

const engine = createBoardEngine()

const renderers: BoardRendererRegistry = {
  image: MyImageNode,
}
</script>

<template>
  <BoardRoot :engine="engine" :renderers="renderers" class="h-screen" />
</template>
```

Nodes whose type is not in the registry fall through to the built-in text renderer.

## Writing a custom renderer

A renderer is a standard Vue component that receives props from the board:

```vue
<!-- MyImageNode.vue -->
<script setup lang="ts">
import type { BoardNode } from '@lupinum/board-core'

defineProps<{
  node: BoardNode
  selected: boolean
  editing: boolean
  beginEdit: () => void
  commitText: (text: string) => void
}>()
</script>

<template>
  <div class="w-full h-full">
    <img
      :src="node.file"
      :alt="node.label"
      class="w-full h-full object-cover"
    />
  </div>
</template>
```

### Renderer props

::field-group
::field{name="node" type="BoardNode"}
The node record: position, size, type, JSON Canvas fields, and metadata.
::

::field{name="selected" type="boolean"}
Whether the node is currently selected.
::

::field{name="editing" type="boolean"}
Whether the node is in text editing mode (double-click triggered).
::

::field{name="beginEdit" type="() => void"}
Call this to enter editing mode programmatically.
::

::field{name="commitText" type="(text: string) => void"}
Commit edited text and exit editing mode.
::
::

Your renderer fills the node's bounding box. Use `width: 100%` and `height: 100%`.

::tip
Use `useBoardEngine()` inside your renderer to access the engine and call commands.
::

::warning
Mark editable elements with `data-editor="true"` so `BoardRoot` lets keyboard events pass through instead of triggering shortcuts.
::

## Slot-based rendering

You can also use named slots on `BoardRoot` instead of (or in addition to) the registry:

```vue
<BoardRoot :engine="engine">
  <template #node:file="{ node, selected }">
    <img :src="node.file" class="w-full h-full object-cover" />
  </template>
</BoardRoot>
```

### Resolution order

1. `#node:{type}` named slot (highest priority)
2. `#node` fallback slot
3. `renderers[type]` from the registry
4. `fallbackRenderer` prop
5. Built-in text renderer (lowest priority)

## Level of Detail (LOD)

`BoardRoot` assigns one of three LOD levels based on screen-space size:

| LOD      | Condition             | What renders                             |
| -------- | --------------------- | ---------------------------------------- |
| `full`   | Selected, or >= 120px | Your custom renderer.                    |
| `simple` | 8–120px               | Minimal placeholder with stripe pattern. |
| `hidden` | < 8px                 | Nothing (unmounted from DOM).            |

Selected nodes always render at `full` LOD regardless of size.

::collapsible

### Custom resize handles

Override resize handle appearance with the `handle` slot:

```vue
<BoardRoot :engine="engine">
  <template #handle="{ handle }">
    <div class="my-custom-handle" :data-resize="handle" />
  </template>
</BoardRoot>
```

The `data-resize` attribute is required — `BoardRoot` uses it to identify which handle was clicked.
