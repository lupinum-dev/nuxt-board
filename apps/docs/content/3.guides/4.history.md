The history plugin records engine actions and replays inverse actions so users can undo and redo. Drags are debounced into single undo steps, and edges are restored alongside their nodes when the connections plugin is installed.

## Setup

```ts
import { createBoardEngine } from '@lupinum/board-core'
import { historyPlugin } from '@lupinum/board-history'

const engine = createBoardEngine({
  extensions: [historyPlugin({ maxSteps: 100, debounceMs: 300 })],
})
```

### Plugin options

::field-group
::field{name="maxSteps" type="number" default="200"}
Maximum undo steps to keep. Older entries are dropped.
::

::field{name="debounceMs" type="number" default="300"}
Rapid changes (like dragging) are coalesced into one undo step. Set to `0` for testing.
::

::

## Undo and redo

```ts
engine.ext.history.undo()
engine.ext.history.redo()

if (engine.ext.history.canUndo()) {
  /* ... */
}

const state = engine.ext.history.getState()
// { undoDepth, redoDepth }

engine.ext.history.clear()
```

Use `engine.ext.history.flushPending()` when you need to commit the current debounced entry before reading stack availability. Read methods such as `canUndo()`, `canRedo()`, and `getState()` do not mutate history state.

Keyboard shortcuts: :kbd{value="meta"}+:kbd{value="Z"} to undo, :kbd{value="meta"}+:kbd{value="shift"}+:kbd{value="Z"} to redo.

::note
When both `historyPlugin` and `connectionPlugin` are installed, undoing a node deletion also restores its connected edges.
::

::collapsible

### Ignored commands

History capture follows command metadata emitted by the engine and first-party features. Camera movement, transient interaction setup/teardown, imports, and selection-only commands are ignored; geometry and content mutations are recorded.

::

::collapsible

### Events

```ts
engine.on('history:push', (entry) => console.log('New step:', entry.label))
engine.on('history:undo', () => console.log('Undo'))
engine.on('history:redo', () => console.log('Redo'))
engine.on('history:clear', () => console.log('History cleared'))
```
